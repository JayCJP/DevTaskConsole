# DevTask Console · 工作台交互设计文档

> 把原本分散在「看板页 / 实例页 / 发布页」的三类信息，收敛到同一个**左中右三栏联动工作台**：左边选 TAPD 需求与实例，中间看 Job 输出与对话，右边管工作区构建/发布/MR。一次选择，三栏联动。
>
> **版本 v1.0** · 2026-11-27 · 基于交互优化版设计稿
> 设计稿：`docs/mockups/agent-web/workbench-three-column-ux.excalidraw`（源文件）/ `.png`（预览）
> 前置版本：`workbench-three-column.excalidraw`（三栏基础版）；更早的 `workbench-redesign.excalidraw`（工坊看板线框）为不同方向的探索稿。

---

## 0. 设计论点与范围

### 0.1 一句话论点

**一个入口选对象，三栏同步呈现「需求 → 会话 → 发布」的完整上下文**；用户不再在三个页面之间来回跳转，危险操作被护栏拦在显式确认之后。

### 0.2 为什么要做

现状（来自现有代码与需求规格 v2.8 第 11.1 节）：

| 页面 | 承载内容                                           | 问题                                               |
| ---- | -------------------------------------------------- | -------------------------------------------------- |
| 看板 | TAPD 需求标题/状态/Bug 数/进度/阶段/工作区绑定     | 看到需求后要切到实例页才能对话                     |
| 实例 | 实例列表 + 当前会话工作区（SESSION OUTPUT + 回复） | 不知道当前实例对应哪个 TAPD 全貌；发布要再切发布页 |
| 发布 | 环境分段器 + 工作区项目构建/MR/批量发布            | 与需求、会话上下文割裂                             |

同一件事（比如"支付网关升级"）的状态散在三个页面，用户需要在脑内做关联。本设计把它们收敛为一屏。

### 0.3 设计边界

- **本设计是交互结构稿**，定义信息层级、操作路径、状态口径与联动规则；不锁定具体像素、颜色值或组件库。
- 新交互优先复用现有 `useConsoleContext()` 中的状态与 action；新增能力（TAPD-实例关联、右键菜单）需前后端配合。
- 遵循需求规格既有铁律：M3-9 多实例不串线、M6-16 Phase 4-6 写操作禁用、R13 pre/prod 护栏、渐进披露 + 侧滑详情。

## 1. 整体信息架构

### 1.1 布局分区

```
┌─────────────────────────────────────────────────────────────────────┐
│ 顶部全局条：标题 · 全局搜索(⌘K) · 快照时刻/通道健康 · 刷新分级 · 开工单 │
├──────────────┬──────────────────────────────┬───────────────────────┤
│ ① 左栏        │ ② 中栏                       │ ③ 右栏                │
│ TAPD · 实例   │ 实例 Job · 输出与对话         │ 工作区 · 构建/发布/MR  │
│ (选对象)      │ (看会话)                      │ (管发布)              │
│              │                              │                       │
│ 选中实例 ─────┼──→ 中栏上下文切换             │                       │
│              │                              │                       │
│              │  选中实例绑定工作区 ──────────┼──→ 右栏项目列表切换    │
└──────────────┴──────────────────────────────┴───────────────────────┘
```

### 1.2 导航定位

- 工作台作为新的主视图，建议纳入现有七项主导航（与看板/实例/发布并列）或作为默认首屏的聚合视图。
- 原有七个页面保留，从工作台可跳转到对应详情页；工作台不替代它们，而是提供"一站式概览 + 高频操作"。
- 详情层继续用侧滑抽屉或跳页，保留来源列表的筛选、滚动位置与选中项。

## 2. 左栏：TAPD 需求 · 实例

**职责**：选择操作对象。一个 TAPD 需求下挂多个实例，选中实例驱动中栏与右栏。

### 2.1 顶部工具条

| 元素                         | 说明                                     | 状态                                       |
| ---------------------------- | ---------------------------------------- | ------------------------------------------ |
| 栏标题「① TAPD 需求 · 实例」 | 固定                                     | 新增布局                                   |
| 筛选控件                     | `我的 / 全部 / 异常`，默认"异常优先"排序 | **新增**                                   |
| `↻ TAPD`                     | 只刷新 TAPD 段（force 穿透 TAPD 缓存）   | 复用现有 `refreshCurrentPage` 中 TAPD 口径 |
| `↻ Story`                    | 只刷新本地 Story/Harness 段              | 复用 `/api/v1/snapshot?segments=local`     |
| `↻ 实例`                     | 只刷新实例注册表与 job 列表              | 复用 `/stories/services` + jobs            |

**交互优化点 1（异常优先 + 双线索选中态 + 筛选）**：

- 排序：失败 > 待盖章 > 运行中 > 空闲。
- 选中态用**左侧色条 + 底色**双线索，不只靠颜色（满足无障碍非颜色线索要求）。
- 刷新时该按钮局部骨架，不全屏转圈；刷新失败只影响对应段并标示来源与更新时间。

### 2.2 TAPD 需求项（一行一条）

每个 TAPD 项展示以下字段（均来自现有 `tapdStorySchema`，不新建数据源）：

| 字段        | 来源                         | 展示形式                                                      |
| ----------- | ---------------------------- | ------------------------------------------------------------- |
| 需求 ID     | `storyId`                    | `#1138260628001031789`，等宽字体                              |
| 标题        | `title`                      | 一行，超长截断 + hover 全称                                   |
| 打开链接    | `tapdUrl` / `parentTapdUrl`  | 「打开 ↗」按钮，新标签打开 TAPD                               |
| 状态        | `statusLabel` / `status`     | 中文标签（如"已发布""开发中"）                                |
| 处理人      | `owner`                      | 中文全名「蔡杰鹏」                                            |
| 子需求      | `children`                   | 父行可折叠，子行缩进                                          |
| Bug 数      | `bugNew` + `bugReopened`     | `Bug 3(新2/重1)`，有 Bug 时用危险色                           |
| 进度        | Harness 阶段 / 进度刻度      | `进度 4/5` + 进度条；仅在流程活跃时展示阶段（与看板口径一致） |
| 迭代/优先级 | `iterationName` / `priority` | 小字辅助信息                                                  |
| 关联实例数  | 本地关联关系                 | `下挂 2 个实例（异常 1 已置顶）`                              |

**状态口径注意**：看板行 `storyId` 是 TAPD 需求 ID，Harness 的 `storyId` 是本地 Story ID，两者不同，必须经绑定工作区拿到本地 Requirement 再判断活跃，避免口径分叉。

### 2.3 实例子项（挂在 TAPD 项下）

一个 TAPD 需求可挂多个实例（**新增关联关系**，当前代码只有工作区↔TAPD 一对一绑定，实例与 TAPD 的直接关联需新建）：

| 字段                   | 来源                   | 展示                                |
| ---------------------- | ---------------------- | ----------------------------------- |
| 实例名 + 本地 Story ID | `storyServices` 注册表 | `实例 A · story-089 (run)`          |
| 运行模式               | `mode`                 | `run` / `fixbugs`                   |
| 状态                   | 服务 inspect 结果      | `● running` / `⚠ failed` / `○ idle` |
| 端口                   | 持久映射               | `:4317`                             |
| Job 数                 | `jobsByStory(storyId)` | `5 jobs`                            |
| 会话保持               | 本地                   | 标注"会话保持"提示不串流            |

**异常优先**：失败实例置顶并用危险色卡片 + 左侧色条；当前选中实例用紫色双线索。

### 2.4 右键菜单（**新增**）

对实例项右键弹出：

| 菜单项          | 行为                                     | 确认                             |
| --------------- | ---------------------------------------- | -------------------------------- |
| 切换为当前实例  | 中栏/右栏切换到该实例上下文              | 直接执行                         |
| 查看 Story 状态 | 打开 Story 详情抽屉                      | 直接执行                         |
| 启动 / 停止服务 | `startStoryService` / `stopStoryService` | 停止需二次确认                   |
| 移除实例        | `removeStoryService`                     | 二次确认，先删关联 cron 再停服务 |
| 复制 Session ID | 复制到剪贴板                             | 直接执行                         |
| 打开工作区      | 跳转工作区页并定位                       | 直接执行                         |

### 2.5 左栏底部说明区

固定显示状态口径摘要与右键菜单示意，帮助用户理解排序与双线索规则。

## 3. 中栏：实例 Job · 输出与对话

**职责**：查看当前实例 Job 的实时输出，并与之交互。详细功能参考现有实例页右侧。

### 3.1 顶部上下文区（三块并列）

| 块        | 内容                                        | 数据来源                                               |
| --------- | ------------------------------------------- | ------------------------------------------------------ |
| 当前实例  | 本地 Story ID、模式、状态、端口、Session ID | `currentStory` / `currentService` / `currentPortLabel` |
| 关联 TAPD | 需求 ID、标题、状态、Bug 数                 | `storyTapdBinding` / TAPD 快照                         |
| 当前 Job  | Job ID、名称、状态、进度、5 步计划/已完成数 | `selectedJob` / `jobDetail`                            |

**交互优化点 2a**：上下文区下沿标注「切换实例保留各流滚动位置、不串流」——对应 M3-9，每实例独立 SSE 与滚动位置，切换不影响其他流。

### 3.2 会话控制条

复用现有实例页的 job 操作：

- `■ 停止`（stop）、`⟳ 复活`（respawn）、`✎ 重命名`（rename）、`📌 置顶`（toggle pin）、`⤴ 独立实例页`（跳页）。
- 删除走二次确认；`{deleted:false}` 如实展示原因。

### 3.3 待盖章吸顶条 + 一键盖章（**新增交互**）

当 Job 某步骤为危险操作且等待确认时：

- 在会话控制条下方显示**吸顶提示条**：`⏸ 等待你盖章：第 3/5 步「git push」为危险操作，未执行`。
- 右侧提供 `✓ 一键盖章放行` 按钮，点击后才继续流程。
- 用户拒绝则走失败分支（`branchTo('failure')`），并在输出中留痕。

**交互优化点 2b**：把"等待确认"从输出流中提升为吸顶条 + 显式按钮，避免用户在长输出里找盖章入口。

### 3.4 SESSION OUTPUT · 实时输出

- 标题 `SESSION OUTPUT · 实时输出（SSE）`，附「自动跟随底部 · 上滑暂停跟随」提示。
- 消息类型：
  - **用户消息**（绿色，靠左）：`你 14:31:02` + 文本。
  - **助手消息**（紫色，缩进）：`助手 14:31:08` + Markdown 渲染文本。
  - **工具调用证据块**（深色底）：`工具调用 · requestStamp（危险操作）` + 命令样例（如 `git push origin feature/pay-gateway → 待盖章，未执行`）。
- 滚动行为（现有）：切换实例时强制恢复跟随并滚到底部；用户上滑离开底部则暂停跟随，滚回 40px 内恢复；ResizeObserver 兜底图片/富文本高度变化。

### 3.5 回复输入区

- `回复消息 · 发送到当前 Job` 标题 + 多行输入框。
- 支持粘贴图片与附件，写入 Story 项目 `.docs/<storyId>/` 目录。
- `发送 ⌘↵` 按钮 + `附件` 按钮。

**交互优化点 2c**：⌘Enter 发送，减少鼠标往返；`useSuggestedReply` 提供建议回复。

## 4. 右栏：工作区 · 构建 / 发布 / MR

**职责**：管理当前实例绑定的工作区项目，执行构建/发布/MR。详细功能参考现有发布页。

### 4.1 环境分段器

| 环境 | 默认态           | 说明                                     |
| ---- | ---------------- | ---------------------------------------- |
| dev  | 可选（当前选中） | 构建分支 `feature/pay-gw`，MR 目标 `dev` |
| pre  | 🔒 默认禁用      | 需显式解锁 + 二次确认 + 写审计           |
| test | 🔒 默认禁用      | 同上                                     |
| prod | 🔒 默认禁用      | 最高风险，R13 护栏                       |

**交互优化点 3a**：pre/prod/test 带锁图标默认禁用，解锁状态不持久化，每次重新确认。

### 4.2 工作区项目表

- 工作区名 + 项目数徽标（如 `pay-gateway-ws · 3 项目`）。
- 每行：项目名、DevOps 应用、检出分支（MR 源）、状态、操作。
- 每行操作：`构建`、`创建 MR`。

**交互优化点 3b**：项目行按构建/MR 状态分色 + 左侧色条：

- `MR !284 已合并` → 绿色
- `MR !185 待评审` → 橙色
- `构建 #2840 失败` → 红色

### 4.3 分支管理

- 当前检出分支、源分支 → MR 目标分支、保护分支（如 `main` 禁止直推）。
- 操作：切换 / 新建 / 比较差异。

### 4.4 批量发布（护栏重点）

- 标题 `批量发布（不可逆 · 二次确认）`。
- **护栏提示条**：`⚠ Harness Phase 4-6 期间写操作禁用（由发布助手负责）`。
- 多行输入框：每行一个制品链接。
- `发布 🔒` 按钮：Phase 4-6 期间置灰，非该区间也需二次确认 + 写审计。

**交互优化点 3c**：M6-16 硬边界——Phase 4-6 期间触发构建/创建 MR/批量发布/停止构建全部禁用并说明原因；按钮置灰而非隐藏，保留可见性。

## 5. 全局交互规则

### 5.1 刷新分级（交互优化点 4）

| 按钮           | 行为                                                                              |
| -------------- | --------------------------------------------------------------------------------- |
| `↻ 仅刷新本栏` | 只刷新当前激活栏的数据源（左栏→TAPD/Story/实例；中栏→jobs；右栏→workspaces+候选） |
| `↻ 全部刷新`   | 刷新全部段                                                                        |
| 局部刷新按钮   | 每栏内部的 TAPD/Story/实例细粒度刷新                                              |

避免为了看一个实例状态触发全量 TAPD 请求（防 429）。刷新中显示局部骨架，失败只影响对应区域并标示来源与更新时间。

### 5.2 快捷键

| 快捷键 | 行为                                |
| ------ | ----------------------------------- |
| `⌘K`   | 全局搜索（需求/实例/工作区）        |
| `⌘↵`   | 中栏回复发送                        |
| `Esc`  | 关闭抽屉/右键菜单，焦点还给触发元素 |

### 5.3 状态可见性

- **非颜色线索**：状态同时用文字/图标（● ⚠ ○ 🔒）+ 颜色，不只靠颜色。
- **异常优先**：失败与待盖章优先进入视野。
- **数据来源标注**：每栏标注来源与快照时刻，缓存/离线状态可见。

### 5.4 窄屏基础降级

- 导航收入菜单/抽屉；三栏改为「列表 → 详情」分屏切换。
- 多列数据转卡片或明确横向滚动，不静默隐藏关键字段。
- 主要操作保持可触达；不构成完整移动端适配承诺。

### 5.5 写操作安全清单

| 操作                           | 确认                      | 审计 |
| ------------------------------ | ------------------------- | ---- |
| 停止/移除实例                  | 二次确认                  | 是   |
| 一键盖章                       | 显式按钮（即确认）        | 是   |
| pre/prod 解锁                  | 显式解锁 + 二次确认       | 是   |
| 批量发布                       | 二次确认 + Phase 4-6 禁用 | 是   |
| 创建 MR / 构建（Phase 4-6 外） | 二次确认                  | 是   |

## 6. 交互优化点对照表

| 编号 | 优化点                                                | 解决问题                                   | 对应规格           |
| ---- | ----------------------------------------------------- | ------------------------------------------ | ------------------ |
| 1    | 异常优先排序 + 双线索选中态 + 筛选                    | 状态不突出、选中态只靠颜色                 | 状态可见性/无障碍  |
| 2    | 不串流保留滚动 + 待确认吸顶 + 一键盖章 + ⌘Enter       | 用户在长输出里找盖章入口、切换实例丢上下文 | M3-9               |

## 9. 验收标准

1. **联动正确**：左栏选中实例后，中栏上下文切换到该实例且各实例滚动位置互不干扰；右栏切到该实例绑定的工作区项目。
2. **异常优先**：失败实例置顶并有危险色 + 色条；选中态同时有色条与底色。
3. **盖章可达**：危险步骤等待时吸顶条可见，一键盖章按钮可点，拒绝走失败分支并留痕。
4. **护栏生效**：pre/prod 默认禁用，解锁需二次确认且不持久化；Phase 4-6 期间所有发布写操作置灰并说明原因。
5. **刷新粒度**：局部刷新只重取对应段，不触发无关 TAPD 请求；刷新中局部骨架，失败只影响对应区域。
6. **非颜色线索**：所有状态同时有文字/图标与颜色，不只靠颜色区分。
7. **键盘可达**：⌘K 搜索、⌘↵ 发送、Esc 关闭浮层均可用。
8. **窄屏降级**：三栏可退化为列表→详情切换，关键字段不丢失。
9. **来源可追溯**：每栏显示数据来源与快照时刻，缓存/离线状态可见。
